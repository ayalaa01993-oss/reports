# מחולל דוחות נוכחות לבדיקות

פרויקט לימודי. התוכנה קוראת דוח נוכחות בפורמט PDF, מחלצת ממנו את השעות, ויוצרת דוח חדש בעיצוב דומה
עם **שעות חדשות** (קרובות סטטיסטית למקור, לא עותק שלו) ואותם תאריכים וימים כמו במקור.

> **כל הנתונים בדוחות שנוצרים בדויים** (שם עובד, שם חברה, תעריף). הדוחות נועדו לבדיקות בלבד.

## שלבי עיבוד

הקוד מחלק את זרימת העבודה לשלבים לפי התפקיד שלהם:

| שלב | מימוש | קלט ופלט |
|-----|-------|----------|
| OCR | `extractors/ocr_engine.py`, `extractors/pdf_to_text.py` ו-`extractors/type1_reader.py` | `ocr_engine.py` הוא היחיד שמייבא `pytesseract`; שאר המחלצים משתמשים בממשק שלו |
| Classifier | `services/report_detector.py` | טקסט OCR ונתיב PDF ל-`ReportType` |
| Parser | `services/report_parser.py` | טקסט OCR ופרטי חודש, למבנה אחיד `AttendanceReport` |
| Transformer | `services/report_transformer.py` | `AttendanceReport` מקור לדוח חדש עם שעות שנדגמו |
| Generator | `services/report_generator.py` | `AttendanceReport` חדש לקובץ PDF או HTML |

המודל המשותף `models/attendance_report.py` מגדיר את `AttendanceReport` ואת שורותיו.
ה-parser מחזיר אותו, ה-Transformer מקבל ומחזיר אותו, וה-Generator מקבל אותו כקלט;
אין המרה למודל report אחר בין השלבים.
שכבת `models/` אינה תלויה ב-`services/` או ב-`extractors/`. שכבת היצירה
(`services/report_generator.py`) מקבלת רק `AttendanceReport` ואינה מייבאת את ה-parser
או מחלקות הלמידה של סוגי הדוחות. נקודת הכניסה `main.py` מחברת בין השלבים.
שירות התזמור `services/report_pipeline.py` בוחר אסטרטגיית עיבוד ממילון לפי `ReportType`;
לכל סוג דוח יש מחלקת אסטרטגיה ייעודית, ללא שרשרת תנאים לבחירת הסוג.
מודלי הדוחות הם immutable (`frozen=True`); אוספי השורות נשמרים כ-tuples
והכותרות והמטא-דאטה כ-mappings לקריאה בלבד.
המסווג מאשר type1 רק כשנמצאו כותרות תאריך/שעות וגם טבלה, ו-type2 רק כשנמצאו
כותרות נוכחות מתאימות. קובץ שאין בו מספיק סימנים מזוהים נדחה עם שגיאה במקום
להיות מנוחש כסוג דוח.

## סוגי הדוחות

| סוג | מקור | שיטת חילוץ | מיקום הסיכום |
|-----|------|------------|---------------|
| type1 | סריקה | חיתוך הטבלה לתאים וקריאת כל תא בנפרד ב-OCR (ספרות בלבד), ותיקון ספרות 1 מול 4 לפי הכלל *יציאה פחות כניסה שווה סה"כ* | בראש הדף |
| type2 | טקסט נקי | חילוץ טקסט וזיהוי תאריכים ושעות בעזרת ביטוי רגולרי | בתחתית הדף |

## דרישות

- Windows עם Python 3.10 ומעלה
- התוכנה Tesseract OCR (פירוט בהמשך)
- הספריות ב-`requirements.txt`

## התקנה

1. פותחים את תיקיית הפרויקט (`reports`) ב-PyCharm ויוצרים לה סביבה וירטואלית (venv) משלה.
2. מתקינים את הספריות **בתוך הסביבה הווירטואלית** (בטרמינל של PyCharm צריך להופיע `(.venv)` בתחילת השורה):

   ```
   pip install -r requirements.txt
   ```

3. מתקינים את Tesseract:
   - מורידים את ההתקנה ל-Windows (למשל מהגרסאות של UB Mannheim).
   - בזמן ההתקנה מסמנים גם את שפת **Hebrew**. היא נחוצה ל-OCR של type2 כאשר ל-PDF אין טקסט מוטמע.
   - הקוד מחפש את `tesseract` ב-`PATH`.
   - אם Tesseract מותקן במקום שאינו ב-`PATH`, מגדירים את `TESSERACT_CMD` עם הנתיב המלא ל-`tesseract.exe`.
     לדוגמה ב-PowerShell:

     ```powershell
     $env:TESSERACT_CMD = "D:\Apps\Tesseract-OCR\tesseract.exe"
     ```

4. בודקים שההתקנה עובדת:

   ```
   tesseract --version
   ```

5. להגדרת גופן עברי אם לא נמצא גופן מתאים אוטומטית, מגדירים את `REPORT_FONT_PATH`
   לנתיב קובץ הגופן (למשל `arial.ttf`). ב-PowerShell:

   ```powershell
   $env:REPORT_FONT_PATH = "D:\Fonts\arial.ttf"
   ```

   נתיבים אישיים מוגדרים במשתני הסביבה ואינם מקודדים בקוד. ברירות המחדל ושמות
   המשתנים מופיעים בקובץ `config.py`.

## מבנה הפרויקט

```
config.py, main.py
data/
    pdf_reports/      דוחות מקור (כאן מניחים את ה-PDF)
    text_reports/     טקסט OCR לדוחות type2 ושורות OCR מובנות לדוחות type1
    debug_images/     תמונות ביניים לדיבוג
    output/           הדוחות שנוצרו
extractors/           קריאה מקבצים (PDF, תמונה, טבלה, תאים)
models/               מבני נתונים
services/             לוגיקה, בדיקות תקינות, ויצירת PDF
tests/                בדיקות אוטומטיות
```

## הרצה

1. מניחים את דוח המקור בתיקייה `data/pdf_reports/`.
2. משנים את שם הקובץ או את פרטי הדוח בפונקציה `run_default_reports` שבקובץ
   `services/report_pipeline.py`.
3. **ב-type1:** הפרמטרים `year` ו-`month` חייבים להיות החודש של **דוח המקור**, כי שורה i בטבלה היא היום i
   בחודש. התאריכים והימים בדוח החדש זהים למקור, ורק השעות חדשות.
4. מריצים:

   ```
   python main.py
   ```

`main.py` הוא נקודת כניסה דקה בלבד; תזמור התהליך נמצא ב-`services/report_pipeline.py`.
טקסט ה-OCR נשמר ב-`data/text_reports/` ונטען משם להמשך התהליך. ב-type1 נשמרים
גם פלטי קריאת התאים בקובץ `<שם המקור>_type1_rows.txt`. כברירת מחדל הדוח נשמר כ-PDF
ב-`data/output/` בשם `<שם המקור>_generated.pdf`. אפשר לבקש HTML דרך הפרמטר
`output_format="html"` בקריאה ל-`make_report`.

כדי לסמן חגים, יוצרים לצד קובצי הטקסט קובץ `<שם המקור>_holidays.txt` עם תאריך אחד
בכל שורה בפורמט `YYYY-MM-DD` (אפשר להוסיף שורות הערה שמתחילות ב-`#`). תאריכי חג
שמופיעים בטקסט OCR עם המילה "חג" או `holiday` מזוהים גם הם. שורות שבת וחג נשמרות
בדוח, מסומנות בעמודת ההערות ומופיעות ללא שעות.

## איך נוצרות השעות

- התוכנה לומדת מהמקור את הממוצע והפיזור של שעת הכניסה ושל אורך המשמרת, וגם את הקשר ביניהם.
- בכל יום נדגם זוג חדש (כניסה, אורך) מההתפלגות הזו, כך שהדוח החדש דומה סטטיסטית אבל אינו עותק.
- ימי החופש והתאריכים נלקחים מהמקור. ההפסקות ב-type2 נדגמות מההפסקות שנמצאו במקור.
- שורות שבת וחג נשמרות ללא שעות; החגים מסומנים בקובץ החגים או בטקסט OCR.
- לפני כל יצירת PDF רצה בדיקת תקינות. אם הדוח לא תקין, לא נוצר קובץ והתוכנה מדווחת על השגיאות.

כללי התקינות הנבדקים כיום:

- **type1:** מספר השורות שווה למספר ימי החודש, אין עבודה בשישי ושבת, יציאה אחרי כניסה, וסה"כ שווה יציאה פחות כניסה.
- **type2:** אין תאריך כפול, סה"כ שווה יציאה פחות כניסה פחות הפסקה, פירוק השעות לאחוזים שווה לסה"כ, שורות שבת וחג ללא שעות, וכל הדוח בחודש אחד.

## בדיקות

מתקינים `pytest` (כלול ב-`requirements.txt`) ומריצים מתיקיית הפרויקט:

```
python -m pytest
```

- הבדיקות משתמשות בנתוני מקור מלאכותיים, ואינן דורשות דוחות אמיתיים.
- בדיקות שיוצרות PDF מדלגות אם לא נמצא גופן עם תמיכה בעברית (Arial ב-Windows).
- בדיקת ה-OCR מדלגת אם Tesseract לא מותקן.

## בעיות נפוצות

| הודעה | סיבה ופתרון |
|-------|--------------|
| `ModuleNotFoundError: No module named 'cv2'` | הספריות הותקנו בפייתון אחר. מתקינים מתוך הסביבה הווירטואלית של הפרויקט. |
| `TesseractNotFoundError` | Tesseract לא מותקן או שהנתיב שגוי. בודקים `TESSERACT_CMD`. |
| `Expected N table rows for M/YYYY, got K` | מספר שורות הטבלה שנקראו שונה ממספר ימי החודש. בודקים ש-`year` ו-`month` הם של דוח המקור, ושקווי הטבלה זוהו נכון (תמונות ב-`data/debug_images`). |
| `No valid attendance rows (with date) found in text` | הטקסט שחולץ מ-type2 לא בפורמט `dd/mm/yyyy` עם שלוש שעות בשורה. פותחים קובץ מ-`data/text_reports/` ובודקים. |
| `No Hebrew-capable font found` | מוסיפים נתיב לגופן עברי ב-`FONT_CANDIDATES` בקובץ `services/base_report.py`. |

## מגבלות ידועות

- אין מעבר עמוד: דוח ארוך מעמוד אחד יגלוש.
- ב-type2 עדיין אין שעות נוספות (125% ו-150%) אלא רק 100% ושבת.
- סוג הדוח מזוהה אוטומטית ב-`services/report_detector.py`; בדוחות type1 עדיין צריך להעביר
  ל-`main.py` את השנה והחודש של דוח המקור.
